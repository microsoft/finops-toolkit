# What's new in FinOps toolkit 15 – October 2026

Most of us already keep an AI assistant open all day. It writes, summarizes, and answers questions. Now that assistant can help you understand and optimize your cloud costs, too. FinOps toolkit 15 brings FinOps expertise and your cost data to the AI tools you already use with a new agent plugin. You can also run FinOps hubs on your own machine, add NAT Gateway support to private FinOps hubs, and get better data for reservations and savings plans. FinOps hubs 15 is faster, more reliable, and more accurate, and Power BI reports, workbooks, alerts, Azure Optimization Engine, and the PowerShell module all got improvements. Read on for details.

## New to the FinOps toolkit?

The FinOps toolkit is an open-source collection of tools and resources helping organizations learn, adopt, and implement FinOps in the Microsoft Cloud. The foundation includes the [Implementing FinOps guide](https://aka.ms/finops/guide) for getting started with native Azure portal tools or custom FinOps solutions. Learn more at the [FinOps toolkit documentation](https://aka.ms/ftk/docs).

## Scale your FinOps impact with AI agents

Picture the staff your manager never gave you: a team of AI agents that know FinOps, work from your own cost data, and welcome every follow-up question. You direct them to find which Azure services drove last month's spend and why. Then they plan the fix, draft a proposal your engineering team can act on, and build the report your leadership asks for. That's the new [FinOps toolkit agent plugin](https://microsoft.github.io/finops-toolkit/agent-plugin): AI agents that do the work, not just answer questions.

The plugin includes five agents: CFO, FinOps practitioner, FinOps hubs database query, FinOps hubs deployment and troubleshooting, and Azure capacity manager. The CFO, FinOps practitioner, and Azure capacity manager work with or without a FinOps hub. They offer FinOps guidance, help with Azure quota and capacity, and answer basic cost questions, like what you spent last month, using Microsoft Cost Management. Connect a FinOps hub and the database query agent takes on bigger questions, like month-over-month trends, forecasts, anomalies, and AI spend by application. Built-in commands handle routine work, like running month-over-month and year-to-date cost reports. See the [plugin documentation](https://learn.microsoft.com/cloud-computing/finops/toolkit/agent-plugin/finops-toolkit-agent-plugin-overview) for details. Agents query your data in read-only mode, so nothing changes in your environment. To go further across Azure, you can also add the full [Azure MCP server](https://learn.microsoft.com/azure/developer/azure-mcp-server/overview).

The plugin uses the [Agent Plugins](https://agent-plugins.org) open standard, so it works across AI platforms that support the standard. See [compatible clients](https://agent-plugins.org/compatible-clients) for the current list. Only the install steps vary:

- **GitHub Copilot CLI:** Run `copilot plugin install microsoft/finops-toolkit`.
- **ChatGPT:** Ask a workspace admin to import the `microsoft/finops-toolkit` GitHub marketplace, then open the **Plugins** tab, select the plugin, and select the plus button to install it.
- **Codex CLI:** Run `codex plugin marketplace add microsoft/finops-toolkit`, then run `codex`, enter `/plugins`, and install the plugin.
- **Claude Cowork:** Select **Customize** > **Plugins** > **Add** > **Add marketplace**, enter `microsoft/finops-toolkit`, then add the plugin.
- **Claude Code:** Run `/plugin marketplace add microsoft/finops-toolkit`, then `/plugin install microsoft-finops-toolkit@finops-toolkit`.

Let us know where you'd like to see this go. We're also looking into a FinOps toolkit MCP server to take this even further.

## Run a FinOps hub on your own machine

Not every question needs a deployed FinOps hub. Maybe you want to prototype FinOps hubs before engaging engineering and deploying Azure resources. Maybe you want to explore the data model, test a query against a large dataset, or work somewhere you can't reach Azure. The new [Run FinOps hubs locally](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/run-hubs-locally) guide shows how to run a FinOps hub in a free container, so what you learn carries over to a deployed FinOps hub. The guide is written so you or your AI assistant can run each step, and the new [Initialize-FinOpsHubLocal](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/initialize-finopshublocal) command sets up everything with one command.

A local FinOps hub is a separate option next to a deployed FinOps hub, not a replacement. You run the container yourself, so there's no scheduled ingestion and no service level agreement (SLA). That makes a local FinOps hub a great fit for exploring, validating, and supporting consulting work. When you need scheduled ingestion, an SLA, and data you can share across your organization, deploy a FinOps hub in Azure.

## NAT Gateway support for private FinOps hubs

Many organizations keep their cloud data off the public internet. If yours is one of them, FinOps hubs 15 gives you more ways to fit private FinOps hubs to your environment. Private FinOps hubs now support a NAT Gateway for controlled outbound access, which suits subscriptions where Azure Policy turns off default outbound access. A new VNet mode covers subscriptions that allow default outbound access and don't need a NAT Gateway.

To use a NAT Gateway, set **Access** to **Private** on the **Advanced** tab of the deployment UI, then select **Deploy NAT Gateway for controlled outbound access**. In PowerShell, run `Deploy-FinOpsHub` with `-NetworkMode` set to `private`, `vnet`, or `public`. When you upgrade, use the same network settings to keep your setup. See [private networking](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/private-networking) for details.

## FinOps hubs are faster, more reliable, and more accurate

FinOps hubs 15 brings a ton of quality improvements, from performance and reliability to data quality. Now's a great time to upgrade, if you're running on an older version. Here are some of the highlights:

**Faster.** Large datasets ingest with less effort, and queries, including the query catalog, run faster.

**More reliable.** Upgrading keeps your data retention settings unless you choose a new value.

**More accurate.** Savings and effective savings rate (ESR) now match across the dashboard Summary and Rate optimization pages, and the SQL VMs without Azure Hybrid Benefit recommendation includes every eligible VM.

Ready to upgrade? See [Create and update FinOps hubs](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/deploy).

## Better data for reservations and savings plans

Getting the most from reservations and savings plans starts with knowing which meters qualify for a commitment discount and which SKUs flex together. FinOps toolkit 15 improves both with a refreshed [commitment discount eligibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/open-data#commitment-discount-eligibility) dataset, a new [instance size flexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/open-data#instance-size-flexibility) (ISF) dataset, and corrected eligibility columns in FinOps hubs price data. The latest datasets refresh weekly on GitHub, and each release includes a snapshot from the time of the release.

If you're building commitment discount eligibility into queries, you can also use the `x_CommitmentDiscountSpendEligibility` and `x_CommitmentDiscountUsageEligibility` columns in the FinOps hubs Prices dataset. These columns tell you which SKUs your commitments apply to. A bug had swapped their values, and FinOps hubs 15 corrects them. `x_CommitmentDiscountSpendEligibility` indicates which SKUs savings plans are eligible for, and `x_CommitmentDiscountUsageEligibility` indicates which SKUs reservations are eligible for. If you have historical Prices data, [upgrade to FinOps hubs 15](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/upgrade) and reingest that data to make sure all of it has the correct values.

The new ISF dataset maps each ARM SKU to its flexibility group and ratio, comes from the Azure Reservations Catalogs API, and covers every Azure region. If you're using Power BI reports or Azure Optimization Engine, you'll want to upgrade those as well to use the new ISF dataset.

If you're building commitment discount automation via scripts, you may also be interested in the new [Get-FinOpsInstanceSizeFlexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopsinstancesizeflexibility) and [Get-FinOpsCommitmentDiscountEligibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopscommitmentdiscounteligibility) commands in the FinOps toolkit PowerShell module. These give you programmatic access to the same data, in a more queryable manner that you can integrate cleanly into existing PowerShell or other scripts.

## Find help in the FinOps toolkit ecosystem

The FinOps toolkit is free and open source, and a growing ecosystem helps you get more out of the toolkit. The new [FinOps toolkit ecosystem page](https://microsoft.github.io/finops-toolkit/ecosystem) lists independent tools and organizations that build on or support the toolkit. While I am biased, there are two I want to call out: a path for official support for the FinOps toolkit and a richer experience for navigating your data in FinOps hubs for free.

While Microsoft Support doesn't provide full support for the FinOps toolkit, [Allyte](https://allyte.com) has introduced new plans to fill that gap. The FinOps toolkit office hours, which Allyte runs, are a great place to start. But if you need more, Allyte offers direct access to experts, regular coaching sessions, and advisory for Microsoft FinOps in general, all from the people closest to the toolkit, when and where you need it.

When I started the FinOps toolkit, I always had a vision of building a native portal experience that makes it easy to understand and optimize costs. Today, FinOps hubs give you that core platform – open, scalable, and extensible – but you're often hit by limitations of reports and dashboards that are never as interactive as you might need them to be. [FinOpsHubs.com](https://finopshubs.com) is an initial step in that direction. And we're happy to offer it to the community **for free**. Your data stays under your control, and you get a richer way to navigate that data in a free, scalable analytics experience designed to evolve around your needs. No data to move. No special access. Just sign in and get answers. And, as the former product manager for Cost analysis in the Azure portal, you'll find it familiar with additions that help you do more than you've been able to in the past. And of course, this is just the start. We're eager to build this out and help you achieve more through AI backed by intelligent tooling that connects people and streamlines processes. We're looking forward to hearing your feedback and seeing where this goes!

Of course, these are just two of the resources mentioned on the ecosystem page. Know a tool or organization that belongs there? [Suggest a listing](https://github.com/microsoft/finops-toolkit/issues/new?template=propose-ecosystem-listing.yaml).

## Other new and noteworthy updates

**In the [Implementing FinOps guide](https://aka.ms/finops/guide):**

- Updated guidance to use current FinOps Framework capability names, like Usage optimization and Governance, policy, and risk. Power BI reports and workbooks use the same names.
- Updated the data dictionary descriptions of several cost and billing columns to match FOCUS 1.2.

**In [FinOps hubs](https://aka.ms/finops/hubs):**

- Improved managed exports, first-time ingestion, and deployments in more regions, including Sweden Central and Japan.
- Improved deployments with Data Explorer on private networks, including when you approve private endpoint connections.
- Improved contracted cost handling so each row's change history shows only meaningful changes.
- Updated the database guide with 27 more columns and the backfill instructions to cover every month in your retention window in one run.
- Updated the dashboard links for Governance, policy, and risk and for FinOps tools and services to go directly to the Microsoft Learn pages.

**In [Power BI reports](https://aka.ms/ftk/pbi):**

- Improved the Governance and Workload optimization reports for larger environments.
- Added support for gzip-compressed CSV exports (`.csv.gz`) in storage reports, which came up in the [October 28 office hours](https://aka.ms/ftk/office-hours).
- Improved storage report refresh for FOCUS 1.2 exports and exports that use earlier FOCUS versions.
- Changed the default **Number of Months** in storage reports from 1 to 3 to show more cost history.
- Improved Advisor recommendation tables and the Reservations tab in the Rate optimization report, which now shows data for Microsoft Customer Agreement accounts.

**In [FinOps workbooks](https://aka.ms/ftk/workbooks) and [FinOps alerts](https://aka.ms/ftk/alerts):**

- Improved the savings plan workbook to show every recommendation and the Azure Hybrid Benefit workbook to include VMs with uppercase names.
- Improved the idle application gateway and idle public IP alerts to return complete results.

**In [Azure Optimization Engine](https://aka.ms/ftk/aoe):**

- Added an [Azure Optimization Engine reference](https://learn.microsoft.com/cloud-computing/finops/toolkit/optimization-engine/reference) for runbooks, schedules, variables, and tables.
- Updated Log Analytics ingestion to use a Data Collection Rule and Ingestion API, the supported path after the Data Collection API deprecation in September 2026. To upgrade an existing deployment, rerun the deployment script with the same options. See [Upgrading AOE](https://learn.microsoft.com/cloud-computing/finops/toolkit/optimization-engine/setup-options#upgrading-aoe).
- Improved the reservation workbooks to keep reservations visible when their SKU is retired.

**In the [PowerShell module](https://aka.ms/ftk/ps):**

- Improved [Deploy-FinOpsHub](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/deploy-finopshub) to accept version values like `13` and `v14` and to support concurrent deployments.
- Improved [Get-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/get-finopscostexport) `-RunHistory` and [Start-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/start-finopscostexport) to return complete run history and export the correct period in positive UTC offsets.
- Raised the minimum `Az.Accounts` version to 2.17.0. Run `Update-Module Az.Accounts` if you're on an older version.

For the complete list, see the [changelog](https://aka.ms/ftk/changes#v15).
