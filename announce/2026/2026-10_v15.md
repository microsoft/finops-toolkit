# What's new in FinOps toolkit 15 – October 2026

Whether you consider yourself a FinOps practitioner, someone enthusiastic about driving cloud efficiency, or were just tasked with reducing cloud costs, the FinOps toolkit has something for you. FinOps toolkit v15 is about meeting you where you already work. A new agent plugin brings FinOps expertise and your cost data into the AI tools you already use, you can run a FinOps hub on your own machine, and private networking for FinOps hubs is easier to plan around. You also get new reservation and commitment discount data, plus improvements and fixes across Power BI reports, workbooks, alerts, the Azure Optimization Engine (AOE), and the PowerShell module. Read on for details.

## New to the FinOps toolkit?

The FinOps toolkit is an open-source collection of tools and resources helping organizations learn, adopt, and implement FinOps in the Microsoft Cloud. The foundation includes the [Implementing FinOps guide](https://aka.ms/finops/guide) for getting started with native Azure portal tools or custom FinOps solutions. Learn more at the [FinOps toolkit documentation](https://aka.ms/ftk/docs).

## Ask your AI assistant about your FinOps data

Most of us already keep an AI assistant open all day, whether it's a favorite desktop app, VS Code, or a terminal. Now imagine asking it which Azure services drove last month's spend and getting an answer grounded in your own FinOps data. FinOps toolkit v15 makes that possible with a new [FinOps toolkit agent plugin](https://microsoft.github.io/finops-toolkit/agent-plugin).

The plugin includes five agents: a CFO, a FinOps practitioner, a FinOps hubs database query agent, a FinOps hubs agent for deploying and troubleshooting, and an Azure capacity manager. The CFO, FinOps practitioner, and capacity manager are ready to help with FinOps guidance and Azure capacity questions with or without a FinOps hub. Connect a FinOps hub and the query agent can answer questions about your cost data. A FinOps hubs KQL skill gives it the schema and a query catalog, so it writes queries against the real `Costs()`, `Prices()`, `Recommendations()`, and `Transactions()` functions instead of guessing at column names.

A few commands cover the most common tasks, like connecting to a FinOps hub, checking its health, and running month-over-month and year-to-date cost reports. The [plugin documentation](https://learn.microsoft.com/cloud-computing/finops/toolkit/agent-plugin/finops-toolkit-agent-plugin-overview) has the full list.

The plugin also registers an Azure MCP server scoped to Data Explorer in read-only mode. It can query your FinOps hub, but it can't change anything in your environment. To install it, run `claude plugin add microsoft/finops-toolkit` in Claude Code or `copilot plugin install microsoft/finops-toolkit` in GitHub Copilot CLI. You'll need to be signed in with `az login` and have Database Viewer access to your FinOps hub's Data Explorer cluster.

The plugin is packaged for GitHub Copilot CLI and Claude, including Claude Code and Cowork. It builds on skills and MCP servers, the same building blocks as [Agent Plugins](https://agent-plugins.org), an open standard for packaging them across AI tools. These tools support the Agent Plugins standard:

- GitHub Copilot
- ChatGPT and Codex
- Cursor
- Kiro
- Visual Studio Code

If you'd like to use the FinOps toolkit plugin in one of them, tell us. We're also looking into a FinOps toolkit MCP server to take this even further, so now's a great time to share what you'd like to see next. You'll find the links at the end of this post.

## Run a FinOps hub on your own machine

Not every FinOps hub question needs a deployed hub. Sometimes you want to explore the data model, test a query against a large dataset, or work somewhere you can't reach Azure. Sometimes you're on a Finance team that wants to get started without waiting on engineering to deploy Azure resources. The new [Run FinOps hubs locally](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/run-hubs-locally) guide walks through running a FinOps hub in the Kusto emulator, a free container. It uses the same KQL, transforms, and open data as a deployed hub, so what you learn locally carries over.

You need Docker with at least 16 GB of memory available to the container, PowerShell 7, and FOCUS cost exports as Parquet files on disk. The guide is written so you or your AI assistant can run each step. The new [Initialize-FinOpsHubLocal](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/initialize-finopshublocal) command sets up the local hub in a running emulator with one command. The release also includes a `finops-hub-local-opendata.kql` file that loads the open data tables. It's generated from the open data CSV files at build time, so your local hub stays in sync with what we publish.

A local hub complements a deployed one. It's built for exploring, validating, and supporting consulting work, so it doesn't include scheduled ingestion or sharing. Your cost data and databases live in folders you choose on your machine, and the guide mounts your exports read-only.

## Private networking for FinOps hubs

FinOps hubs have supported private networking for several releases. FinOps toolkit v15 makes private deployments work in more environments.

Private mode now includes an opt-in NAT Gateway that gives the FinOps hub explicit outbound access. That lets private deployments work in subscriptions with an Azure Policy that requires subnets to have default outbound access disabled. NAT Gateway adds cost when you enable it. To turn it on, set **Access** to **Private** on the **Advanced** tab of the deployment UI, then select **Deploy NAT Gateway for controlled outbound access**. In PowerShell, run `Deploy-FinOpsHub` with `-NetworkMode private`. The new `-NetworkMode` parameter also accepts `public` and `vnet`, which uses private endpoints with default outbound access.

Deployment options aren't remembered from one deployment to the next, so set the same network options every time you upgrade. In PowerShell, that means passing the same `-NetworkMode` each time.

We also made the ownership model clearer. The FinOps toolkit manages the hub virtual network, and customer-managed private endpoints are the preferred way to give people and tools private access to a hub. Virtual network peering still works as a secondary option. Both are covered in the [private networking](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/private-networking) documentation. And deployments with Data Explorer now complete when you approve private endpoint connections, without a `ServiceIsInMaintenance` error.

## Faster, more reliable, more accurate FinOps hubs

FinOps toolkit v15 is a quality release for FinOps hubs, so it's a great time to upgrade. Here's what you get:

- **Performance:** Queries use case-insensitive comparisons that take advantage of the term index, so they run faster on large datasets. Dimension lookups during ingestion use a faster operator, and Data Factory puts less memory pressure on ingestion.
- **Reliability:** Redeploys and upgrades keep your data retention settings unless you specify a new value. Managed exports get the role they need through Data Factory. Triggers deploy in regions without a time zone mapping, like Sweden Central, and managed export triggers validate in Japan. The first ingestion for a scope, dataset, and month runs without a `PathNotFound` error, most noticeably for reservation recommendation exports.
- **Data quality:** Commitment purchases no longer inflate savings and effective savings rate in the dashboard. Commitment discount savings are accurate when duplicate reservation price rows exist. FOCUS 1.0 cost data is labeled correctly in `x_SourceVersion`. `ContractedCost` is only rewritten when it needs to be, which keeps the `x_SourceValues` audit trail clean. The SQL VMs without Azure Hybrid Benefit recommendation now includes VMs with uppercase names.

Ready to upgrade? See [Create and update FinOps hubs](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/deploy).

## Plan reservations and savings plans with better data

Planning reservations and savings plans runs on data: which SKUs flex together, which meters qualify for a commitment discount, and which columns tell you so. FinOps toolkit v15 improves all three with a new instance size flexibility dataset, a refreshed commitment discount eligibility dataset, and PowerShell commands to look both up. FinOps hubs also get a fix for the commitment discount eligibility price columns.

Reservation tools depend on instance size flexibility (ISF) data to group SKUs and compare sizes. Microsoft retired the static files that held this data, so v15 adds a new [Instance size flexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/open-data#instance-size-flexibility) dataset to open data. It maps each ARM SKU to its flexibility group and ratio, is sourced from the Azure Reservations Catalogs API, and covers every physical Azure region. Ratios use the same normalized scale as the retired files. Power BI reports and the Azure Optimization Engine workbooks were both updated to use this new dataset.

Two new PowerShell commands, [Get-FinOpsInstanceSizeFlexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopsinstancesizeflexibility) and [Get-FinOpsCommitmentDiscountEligibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopscommitmentdiscounteligibility), give you programmatic access to this data in PowerShell.

The [commitment discount eligibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/open-data#commitment-discount-eligibility) dataset is up to date, too. It includes the latest meters and no longer lists retired ones. We refresh both datasets weekly in the dev branch, so the newest versions are always there. The files in each release are a snapshot from the time of the release.

FinOps hubs also report the right values in `x_CommitmentDiscountSpendEligibility` and `x_CommitmentDiscountUsageEligibility`. The spend column now reports savings plan pricing and the usage column reports reservation pricing, matching FOCUS. Upgrade to v15 and reingest your historical prices, and your whole price history lines up with the corrected values.

## Other new and noteworthy updates

**In the [Implementing FinOps guide](https://aka.ms/finops/guide):**

- Updated guidance to use current FinOps Framework capability names, like Usage optimization and Governance, policy, and risk. Power BI reports and workbooks use the same names.
- Updated the data dictionary descriptions of several cost and billing columns to match FOCUS 1.2.

**In [FinOps hubs](https://aka.ms/finops/hubs):**

- Updated the hub database guide to explain how columns are organized, added 27 missing columns, and corrected the `Costs()` column reference.
- Updated the backfill instructions to use `config_StartBackfillProcess`, which backfills every month in your retention window in one run. Microsoft Customer Agreement (MCA) billing accounts and profiles can backfill with Cost Management exports or `Start-FinOpsCostExport` instead.
- Updated the dashboard links for Governance, policy, and risk and for FinOps tools and services to go directly to the Microsoft Learn pages.

**In [Power BI reports](https://aka.ms/ftk/pbi):**

- Changed Azure Resource Graph queries to run per subscription batch to avoid payload size errors in the Governance and Workload optimization reports.
- Changed the default **Number of Months** in storage reports from 1 to 3 to show more cost history.
- Storage reports now read gzip-compressed CSV exports (`.csv.gz`). This came up in the [October 28 office hours](https://aka.ms/ftk/office-hours).
- Storage reports refresh cleanly for FOCUS 1.2 exports and for exports that use earlier FOCUS versions.
- The Reservations tab in the Rate optimization report now shows data for MCA accounts.
- Report templates now open with empty storage and cluster settings, ready for your own data source.

**In [FinOps workbooks](https://aka.ms/ftk/workbooks):**

- The savings plan workbook now shows every recommendation.
- The Azure Hybrid Benefit workbook "VM Latest Change Last 7 days" tile now returns results, and SQL VM queries include VMs with uppercase names.

**In [FinOps alerts](https://aka.ms/ftk/alerts):**

- Idle application gateway and idle public IP queries now return complete results.

**In [Azure Optimization Engine](https://aka.ms/ftk/aoe):**

- Added an [Azure Optimization Engine reference](https://microsoft.github.io/finops-toolkit/optimization-engine/reference) for runbooks, schedules, variables, and tables.
- Changed Log Analytics ingestion from the Data Collection API, which is deprecated in September 2026, to a Data Collection Rule and Ingestion API.
- Reservations stay in the reservation workbooks when their SKU is no longer sold.
- Azure RBAC assignment exports no longer call the Azure Classic administrators endpoint, which was deprecated May 1, 2026.

**In the [PowerShell module](https://aka.ms/ftk/ps):**

- [Deploy-FinOpsHub](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/deploy-finopshub) now works with single-part and `v`-prefixed `-Version` values, like `13` and `v14`, and with concurrent deployments.
- [Get-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/get-finopscostexport) `-RunHistory` returns the complete run history.
- [Start-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/start-finopscostexport) exports the correct period in positive UTC offsets.

For the complete list, see the [changelog](https://aka.ms/ftk/changes#v15).

## What's next

We're already starting the FinOps toolkit v16 release cycle with updates to FinOps Explorer and the Azure SRE Agent, and FOCUS 1.5 is coming in v17. Expect to hear more by the end of the year. Here's what's in development on the [roadmap](https://learn.microsoft.com/cloud-computing/finops/toolkit/roadmap):

- FinOps Explorer, an interactive, cross-platform terminal UI for FinOps scanning and exploration.
- An Azure SRE Agent template for FinOps and capacity management.
- FOCUS 1.5 support across FinOps hubs, Power BI reports, agent plugins, and documentation.
- A FinOps toolkit MCP server, which we're looking into.
- Quota, capacity, and savings plan recommendations in FinOps hubs, along with dashboards for AI billing, tokenomics, and capacity.
- Security hardening for FinOps hubs, including opt-in Key Vault role-based access control and the option to disable storage Shared Key access.
- AI-assisted triage and repository automation with GitHub Agentic Workflows.

The roadmap is driven by what you tell us you need. [Create an issue](https://aka.ms/ftk/ideas) or [start a discussion](https://aka.ms/ftk/discuss) and let us know what you'd like to see next, including what you want from a FinOps toolkit MCP server.
