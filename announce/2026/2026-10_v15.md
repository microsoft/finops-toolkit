# What's new in FinOps toolkit 15 – October 2026

Most of us already keep an AI assistant open all day. It writes, summarizes, and answers questions, so why shouldn't it help you understand and optimize your cloud costs, too? FinOps toolkit v15 makes that happen with a new agent plugin that brings FinOps expertise and your cost data into the AI tools you already use. You can also run FinOps hubs on your own machine, plan around private networking with an opt-in NAT Gateway, and plan reservations and savings plans with new commitment discount data. Power BI reports, workbooks, alerts, Azure Optimization Engine (AOE), and the PowerShell module all got improvements and fixes, too. Read on for details.

## New to the FinOps toolkit?

The FinOps toolkit is an open-source collection of tools and resources helping organizations learn, adopt, and implement FinOps in the Microsoft Cloud. The foundation includes the [Implementing FinOps guide](https://aka.ms/finops/guide) for getting started with native Azure portal tools or custom FinOps solutions. Learn more at the [FinOps toolkit documentation](https://aka.ms/ftk/docs).

## Leverage AI to scale your FinOps impact

Imagine working alongside an AI agent that understands FinOps and your data. Ask which Azure services drove last month's spend, then have it plan a fix, draft a proposal for engineering, or build the report your leadership asks for, all grounded in your own cost data. FinOps toolkit v15 brings that closer with a new [FinOps toolkit agent plugin](https://microsoft.github.io/finops-toolkit/agent-plugin).

The plugin includes five agents: a CFO, FinOps practitioner, FinOps hubs database query agent, FinOps hubs agent for deploying and troubleshooting, and Azure capacity manager. The CFO, FinOps practitioner, and capacity manager can offer FinOps guidance, answer limited cost questions with the Azure Cost Management access you already have, and help with Azure capacity, with or without a FinOps hub. Connect a FinOps hub and the query agent goes further, tackling complex questions like month-over-month trends, anomaly detection, and forecasting across your full cost, price, and recommendation data. A FinOps hubs KQL skill gives it the schema and a query catalog, so it writes queries against the real Costs, Prices, Recommendations, and Transactions datasets instead of guessing.

A few commands cover the most common tasks, like connecting to a FinOps hub, checking its health, and running month-over-month and year-to-date cost reports. The [plugin documentation](https://learn.microsoft.com/cloud-computing/finops/toolkit/agent-plugin/finops-toolkit-agent-plugin-overview) has the full list.

The plugin also registers an Azure MCP server scoped to Data Explorer in read-only mode, so it can query your FinOps hub without changing anything in your environment. If you need to go further, you can add the full [Azure MCP server](https://github.com/Azure/azure-mcp) yourself. We kept the plugin's server scoped to avoid bloating your agent's context.

The plugin builds on [Agent Plugins](https://agent-plugins.org), an open standard, so it works across the AI platforms that support the standard, such as GitHub Copilot, ChatGPT, and Claude. Refer to [compatible clients](https://agent-plugins.org/compatible-clients) for a full list of currently supported tools and platforms.

To install it in GitHub Copilot CLI, run `copilot plugin install microsoft/finops-toolkit`. In Claude Cowork or Claude Code, run `/plugin marketplace add microsoft/finops-toolkit`, then `/plugin install microsoft-finops-toolkit@finops-toolkit`. Other tools have their own install commands, so check their documentation. The plugin documentation covers the sign-in and permissions you need to connect to a FinOps hub.

Let us know where you'd like to see this go. We're also looking into a FinOps toolkit MCP server to take this even further.

## Run a FinOps hub on your own machine

Not every question needs a deployed FinOps hub. Maybe you want to explore the data model, test a query against a large dataset, or work somewhere you can't reach Azure. Maybe you just want to prototype FinOps hubs before engaging engineering and deploying Azure resources. The new [Run FinOps hubs locally](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/run-hubs-locally) guide walks through running a FinOps hub in the Kusto emulator, a free container. It uses the same KQL, transforms, and open data as a deployed hub, so what you learn locally carries over.

You need Docker with at least 16 GB of memory available to the container, PowerShell 7, and FOCUS cost exports as Parquet files on disk. The guide is written so you or your AI assistant can run each step. The new [Initialize-FinOpsHubLocal](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/initialize-finopshublocal) command sets up the local hub in a running emulator with one command and loads all the tables and datasets, just like a normal FinOps hubs instance.

A local hub is a separate way to use FinOps hubs, not a replacement for a deployed one. It's built for exploring, validating, and supporting consulting work. It doesn't come with scheduled ingestion or a service level agreement (SLA) like a deployed hub does, so use a deployed hub when you need those and want to share data across your organization. Your cost data and databases live in folders you choose on your machine, so they're still there when you restart the container.

## Private networking for FinOps hubs

If your organization needs to keep its FinOps hub off the public internet, FinOps toolkit v15 makes private networking easier to adopt. It adds explicit network modes, and private mode now includes an opt-in NAT Gateway that gives the FinOps hub explicit outbound access. That lets private deployments work in subscriptions with an Azure Policy that requires subnets to have default outbound access disabled. NAT Gateway adds cost when you enable it. To turn it on, set **Access** to **Private** on the **Advanced** tab of the deployment UI, then select **Deploy NAT Gateway for controlled outbound access**. In PowerShell, run `Deploy-FinOpsHub` with `-NetworkMode private`. The new `-NetworkMode` parameter also accepts `public` and `vnet`, which uses private endpoints with default outbound access.

When you upgrade, pass the same network options to keep your network setup: the same **Access** setting in the deployment UI or the same `-NetworkMode` in PowerShell. Private mode needs FinOps hubs version 15 or later. If your scripts use `-DisablePublicAccess`, it still works and maps to `vnet`, so move to `-NetworkMode` when you're ready.

We also made the ownership model clearer. The FinOps toolkit manages the hub virtual network, and customer-managed private endpoints are the preferred way to give people and tools private access to a hub. Virtual network peering still works as a secondary option. Both are covered in the [private networking](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/private-networking) documentation. Deployments with Data Explorer also complete smoothly when you approve private endpoint connections.

## FinOps hubs are faster, more reliable, and more accurate

FinOps toolkit v15 is a quality release for FinOps hubs, so it's a great time to upgrade. From performance and reliability to data quality, there's something for everyone. Here's what you get:

**Faster queries and ingestion.** Large queries run faster because they now use the engine's term index instead of scanning every row. Lookups during ingestion are quicker, too, and Data Factory uses less memory when it filters out empty files.

**Smoother deployments and upgrades:**

- Upgrades protect your data. Redeploying or upgrading keeps your data retention settings unless you specify a new value, so historical data isn't purged by accident.
- Managed exports work out of the box. Exports that failed with an `Unauthorized` error because Data Factory was missing a required role now get that role automatically.
- Deployments work in more regions. Data Factory triggers failed to deploy in regions like Sweden Central, and managed export triggers failed validation in Japan. Both now work.
- New data ingests cleanly. The first ingestion for a scope, dataset, and month, which most often affected reservation recommendation exports, no longer fails with a `PathNotFound` error.

**More trustworthy savings.** Savings and effective savings rate (ESR) in the dashboard were inflated by commitment purchases. The Summary and Rate optimization tiles now exclude purchases consistently, so the numbers reflect what you actually saved. Commitment discount savings were also understated when duplicate reservation price rows existed. They now use the highest on-demand price, so savings are accurate.

**Cleaner data:**

- Contracted cost values are only recalculated when they need to be. Before, hubs rewrote millions of values that were already correct, which cluttered the audit trail that records changes to each row.
- The SQL VMs without Azure Hybrid Benefit recommendation now includes every eligible VM. Matching was case sensitive, so VMs with uppercase names were skipped, and VMs with duplicate names were dropped.

Ready to upgrade? See [Create and update FinOps hubs](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/deploy).

## Plan reservations and savings plans with better data

Planning reservations and savings plans depends on data: Which SKUs flex together, which meters qualify for a commitment discount, and where you can see that eligibility in your price data. FinOps toolkit v15 improves all three with a new instance size flexibility dataset, a refreshed commitment discount eligibility dataset, and PowerShell commands to look both up. FinOps hubs also get a fix for the commitment discount eligibility price columns.

Reservation tools depend on instance size flexibility (ISF) data to group SKUs and compare sizes. The new [Instance size flexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/open-data#instance-size-flexibility) dataset in open data replaces the retired ISF ratio files that Power BI reports and the Azure Optimization Engine used to rely on. It maps each ARM SKU to its flexibility group and ratio, is sourced from the Azure Reservations Catalogs API, and covers every Azure region. If you're using Power BI reports or Azure Optimization Engine, you'll want to upgrade those as well to ensure you're leveraging the new ISF dataset.

If you're building commitment discount automation via scripts, you may also be interested in the new [Get-FinOpsInstanceSizeFlexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopsinstancesizeflexibility) and [Get-FinOpsCommitmentDiscountEligibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopscommitmentdiscounteligibility) commands in the FinOps toolkit PowerShell module. These give you programmatic access to the same data, in a more queryable manner that you can integrate cleanly into existing PowerShell or other scripts.

The [commitment discount eligibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/open-data#commitment-discount-eligibility) dataset is up to date, too. It includes the latest meters and no longer lists retired ones. We refresh both datasets weekly in the dev branch, so the newest versions are always there. The files in each release are a snapshot from the time of the release.

FinOps hubs also report the right values in `x_CommitmentDiscountSpendEligibility` and `x_CommitmentDiscountUsageEligibility`. The spend column now reports savings plan pricing and the usage column reports reservation pricing, matching FOCUS. Upgrade to FinOps toolkit v15 and [reingest your historical prices](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/upgrade), and your whole price history lines up with the corrected values.

## Other new and noteworthy updates

**In the [Implementing FinOps guide](https://aka.ms/finops/guide):**

- Updated guidance to use current FinOps Framework capability names, like Usage optimization and Governance, policy, and risk. Power BI reports and workbooks use the same names.
- Updated the data dictionary descriptions of several cost and billing columns to match FOCUS 1.2.

**In [FinOps hubs](https://aka.ms/finops/hubs):**

- Updated the hub database guide to explain how columns are organized, added 27 missing columns, and corrected the `Costs()` column reference.
- Updated the backfill instructions to use `config_StartBackfillProcess`, which backfills every month in your retention window in one run. Microsoft Customer Agreement (MCA) billing accounts and profiles can backfill with Cost Management exports or `Start-FinOpsCostExport` instead.
- Updated the dashboard links for Governance, policy, and risk and for FinOps tools and services to go directly to the Microsoft Learn pages.
- Fixed FOCUS 1.0 cost data being labeled as FOCUS 1.2 in `x_SourceVersion`. FOCUS 1.0 rows also skipped 1.0-specific fixes, like the savings plan purchase charge frequency correction.

**In [Power BI reports](https://aka.ms/ftk/pbi):**

- Changed Azure Resource Graph queries to run per subscription batch to avoid payload size errors in the Governance and Workload optimization reports.
- Changed the default **Number of Months** in storage reports from 1 to 3 to show more cost history.
- Storage reports now read gzip-compressed CSV exports (`.csv.gz`). This came up in the [October 28 office hours](https://aka.ms/ftk/office-hours). Thanks to [RolandKrummenacher](https://github.com/RolandKrummenacher) on GitHub for contributing this fix.
- Advisor recommendation tables return complete results.
- Storage reports refresh cleanly for FOCUS 1.2 exports and for exports that use earlier FOCUS versions.
- The Reservations tab in the Rate optimization report now shows data for MCA accounts.
- Report templates now open with empty storage and cluster settings, ready for your own data source.

**In [FinOps workbooks](https://aka.ms/ftk/workbooks):**

- The savings plan workbook now shows every recommendation.
- The Azure Hybrid Benefit workbook "VM Latest Change Last 7 days" tile now returns results, and SQL VM queries include VMs with uppercase names.

**In [FinOps alerts](https://aka.ms/ftk/alerts):**

- Idle application gateway and idle public IP queries now return complete results.

**In [Azure Optimization Engine](https://aka.ms/ftk/aoe):**

- Added an [Azure Optimization Engine reference](https://learn.microsoft.com/cloud-computing/finops/toolkit/optimization-engine/reference) for runbooks, schedules, variables, and tables.
- Log Analytics ingestion now uses a Data Collection Rule and Ingestion API, the supported path after the Data Collection API deprecation in September 2026. Existing deployments pick it up when you [upgrade by rerunning the deployment script](https://learn.microsoft.com/cloud-computing/finops/toolkit/optimization-engine/setup-options#upgrading-aoe).
- Reservations stay in the reservation workbooks when their SKU is no longer sold.
- Azure RBAC assignment exports no longer call the Azure Classic administrators endpoint, which was deprecated May 1, 2026.
- The Reservations Usage workbook works with the current consumption table schema.

**In the [PowerShell module](https://aka.ms/ftk/ps):**

- [Deploy-FinOpsHub](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/deploy-finopshub) now works with single-part and `v`-prefixed `-Version` values, like `13` and `v14`, and with concurrent deployments.
- [Get-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/get-finopscostexport) `-RunHistory` returns the complete run history.
- [Start-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/start-finopscostexport) exports the correct period in positive UTC offsets.
- The module now requires `Az.Accounts` 2.17.0 or later, so the `Get-AzAccessToken -AsSecureString` parameter is always available. Run `Update-Module Az.Accounts` if you're on an older version.

For the complete list, see the [changelog](https://aka.ms/ftk/changes#v15).

## What's next

We're already starting the FinOps toolkit v16 release cycle with updates to FinOps Explorer and the Azure SRE Agent, and FOCUS 1.5 is coming in v17. Expect to hear more by the end of the year. Here's what's in development on the [roadmap](https://learn.microsoft.com/cloud-computing/finops/toolkit/roadmap):

- FinOps Explorer, an interactive, cross-platform terminal UI for FinOps scanning and exploration.
- An Azure SRE Agent template for FinOps and capacity management.
- FOCUS 1.5 support across FinOps hubs, Power BI reports, agent plugins, and documentation.
- A FinOps toolkit MCP server, which we're looking into.
- Quota, capacity, and savings plan recommendations in FinOps hubs, along with dashboards for AI billing, tokenomics, and capacity.
- Security hardening for FinOps hubs, including opt-in Key Vault role-based access control and the option to disable storage Shared Key access.
- AI-assisted triage and repository automation with GitHub Agentic Workflows.

The roadmap is driven by what you tell us you need. [Create an issue](https://aka.ms/ftk/ideas) or [start a discussion](https://aka.ms/ftk/discuss) and let us know what you'd like to see next, including what you want from a FinOps toolkit MCP server.
