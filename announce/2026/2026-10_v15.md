# What's new in FinOps toolkit 15 – October 2026

Whether you consider yourself a FinOps practitioner, someone enthusiastic about driving cloud efficiency, or were just tasked with reducing cloud costs, the FinOps toolkit has something for you. This release is about working with your FinOps data wherever you already are. There's a new plugin that puts FinOps hubs inside Claude Code and GitHub Copilot CLI, a guide for running a hub on your own machine, and private networking modes for hubs that need to stay off the public internet. We also replaced the instance size flexibility files that Microsoft retired with open data the toolkit generates itself. Read on for details.

## New to the FinOps toolkit?

The FinOps toolkit is an open-source collection of tools and resources helping organizations learn, adopt, and implement FinOps in the Microsoft Cloud. The foundation includes the [Implementing FinOps guide](https://aka.ms/finops/guide) for getting started with native Azure portal tools or custom FinOps solutions. Learn more at the [FinOps toolkit documentation](https://aka.ms/ftk/docs).

## Ask your coding agent about your FinOps data

Most of us already have an agent open in a terminal all day. It can read your code, but it has no idea what your cloud costs. v15 fixes that with a new [FinOps toolkit agent plugin](https://microsoft.github.io/finops-toolkit/agent-plugin) for Claude Code and GitHub Copilot CLI.

The plugin includes five agents: a CFO, a FinOps practitioner, a FinOps hubs database query agent, a hubs agent for deploying and troubleshooting, and an Azure capacity manager. There are four commands for connecting to a hub, checking its health, and running month-over-month and year-to-date cost reports. A FinOps hubs KQL skill gives the agents the schema and a query catalog, so they write queries against the real `Costs()`, `Prices()`, `Recommendations()`, and `Transactions()` functions instead of guessing at column names.

The plugin also registers an Azure MCP server scoped to Data Explorer in read-only mode. It can query your hub, but it can't change anything in your environment. To install it, run `claude plugin add microsoft/finops-toolkit` in Claude Code or `copilot plugin install microsoft/finops-toolkit` in GitHub Copilot CLI. You'll need to be signed in with `az login` and have Database Viewer access to your hub's Data Explorer cluster.

This is the first release of the plugin and we want to hear what's missing. Tell us which agents and commands you'd use every week.

## Run a FinOps hub on your own machine

Not every hub question needs a deployed hub. Sometimes you want to explore the data model, test a query against a large customer dataset, or work somewhere you can't reach Azure. The new [Run hubs locally](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/run-hubs-locally) guide walks through running a hub in the Kusto emulator, a free container. It uses the same KQL, transforms, and open data as a deployed hub, so what you learn locally carries over.

You need Docker with at least 16 GB of memory available to the container, PowerShell 7, and FOCUS cost exports as Parquet files on disk. The new [Initialize-FinOpsHubLocal](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/initialize-finopshublocal) command sets up the local hub in a running emulator with one command. The release also includes a `finops-hub-local-opendata.kql` file that loads the open data tables. It's generated from the open data CSV files at build time, so your local hub stays in sync with what we publish.

A local hub isn't a replacement for a deployed one. It doesn't have scheduled ingestion, networking, or security. But for exploration, validation, and consulting work, it's a lot faster than standing up Azure resources first.

## Private networking for FinOps hubs

FinOps hubs now support virtual network and private network modes. If your organization requires data services to stay off the public internet, you can deploy a hub that way from the start. Private mode includes opt-in NAT Gateway support for outbound access. Keep in mind that NAT Gateway adds cost when you enable it.

We also made the ownership model clearer. The FinOps toolkit manages the hub virtual network, and customer-managed private endpoints are the preferred way to give people and tools private access to a hub. Virtual network peering still works as a secondary option. Both are covered in the [private networking](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/private-networking) documentation.

Private deployments also got several fixes in this release. Private mode subnets no longer trip Azure Policy that requires default outbound access to be disabled, and deployments with Data Explorer no longer fail with a `ServiceIsInMaintenance` error when approving private endpoint connections.

## Instance size flexibility without the retired files

Reservation tooling depends on instance size flexibility (ISF) data to group SKUs and compare sizes. The external files we used for that were retired, which left hubs, Power BI reports, and the Azure Optimization Engine pointing at data nobody maintains anymore.

v15 adds an [Instance size flexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/open-data#instance-size-flexibility) open data dataset that maps each ARM SKU to its flexibility group and ratio. It's sourced from the Azure Reservations Catalogs API, covers every physical Azure region instead of a fixed list, and refreshes weekly. New SKUs show up and retired SKUs age out without us republishing anything. The ratios use the same scale as the retired files and match them for 1,223 of the 1,291 rows the two share. Power BI reports and the Azure Optimization Engine workbooks now use it.

The PowerShell module has two new commands to generate open data files: [Get-FinOpsInstanceSizeFlexibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopsinstancesizeflexibility) and [Get-FinOpsCommitmentDiscountEligibility](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/data/get-finopscommitmentdiscounteligibility).

If you use the commitment discount eligibility dataset from v14, there are fixes you should know about. The weekly refresh was timing out, which left the dataset unchanged since v14. That's fixed, and retired meters now age out while previously missed meters are included. Also, `x_CommitmentDiscountSpendEligibility` and `x_CommitmentDiscountUsageEligibility` had each other's values since v14. The spend column now reports savings plan pricing and the usage column reports reservation pricing. Prices ingested after you upgrade carry the corrected values, but rows you already ingested keep the old ones until you reingest them.

## Other new and noteworthy updates

**In the [Implementing FinOps guide](https://aka.ms/finops/guide):**

- Added a [FinOps toolkit ecosystem page](https://microsoft.github.io/finops-toolkit/ecosystem) listing independent tools and organizations that build on or support the toolkit.
- Updated guidance to use current FinOps Framework capability names, like Usage optimization and Governance, policy, and risk. Power BI reports and workbooks use the same names.
- Fixed outdated descriptions of several cost and billing columns in the data dictionary to match FOCUS 1.2.

**In [FinOps hubs](https://aka.ms/finops/hubs):**

- Fixed hub redeploys and upgrades resetting data retention and purging historical data. Retention now stays as configured unless you specify a new value.
- Fixed commitment purchases inflating savings and effective savings rate in the dashboard.
- Fixed understated commitment discount savings when duplicate reservation price rows exist.
- Fixed FOCUS 1.0 cost data being labeled as FOCUS 1.2 in `x_SourceVersion`.
- Fixed managed exports failing with an `Unauthorized` error because Data Factory was missing a required role.
- Fixed Data Factory trigger deployment failures in regions without a time zone mapping, like Sweden Central.
- Fixed a `PathNotFound` error on the first ingestion for a scope, dataset, and month, most often hit by reservation recommendation exports.
- Changed hub queries to use case-insensitive comparisons that take advantage of the term index, so they run faster on large datasets.
- Updated the hub database guide to explain how columns are organized, added 27 missing columns, and corrected the `Costs()` column reference.
- Documented that the `config_RunBackfillJob` backfill option isn't supported on Microsoft Customer Agreement (MCA) billing accounts or profiles, and updated the backfill instructions to use `config_StartBackfillProcess`.

**In [Power BI reports](https://aka.ms/ftk/pbi):**

- Changed Azure Resource Graph queries to run per subscription batch to avoid payload size errors in the Governance and Workload optimization reports.
- Changed the default **Number of Months** in storage reports from 1 to 3 to show more cost history.
- Fixed storage reports showing no data for gzip-compressed CSV exports (`.csv.gz`).
- Fixed storage report refresh errors for FOCUS 1.2 exports and for exports that use earlier FOCUS versions.
- Fixed the Reservations tab in the Rate optimization report showing no data for MCA accounts.
- Fixed report templates opening with a preconfigured demo data source.

**In [FinOps workbooks](https://aka.ms/ftk/workbooks):**

- Fixed the savings plan workbook dropping recommendations.
- Fixed the Azure Hybrid Benefit workbook "VM Latest Change Last 7 days" tile always returning no rows, and SQL VM queries missing VMs with uppercase names.

**In [FinOps alerts](https://aka.ms/ftk/alerts):**

- Fixed idle application gateway and idle public IP queries silently dropping results.

**In [Azure optimization engine](https://aka.ms/ftk/aoe):**

- Added an [Azure Optimization Engine reference](https://microsoft.github.io/finops-toolkit/optimization-engine/reference) for runbooks, schedules, variables, and tables.
- Changed Log Analytics ingestion from the Data Collection API, which is deprecated in September 2026, to a Data Collection Rule and Ingestion API.
- Fixed reservations disappearing from the reservation workbooks when their SKU is no longer sold.
- Fixed Azure RBAC assignment exports calling the Azure Classic administrators endpoint, which was deprecated May 1, 2026.

**In the [PowerShell module](https://aka.ms/ftk/ps):**

- Fixed [Deploy-FinOpsHub](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/hubs/deploy-finopshub) failing with certain `-Version` values and concurrent deployments.
- Fixed [Get-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/get-finopscostexport) `-RunHistory` not returning the complete run history.
- Fixed [Start-FinOpsCostExport](https://learn.microsoft.com/cloud-computing/finops/toolkit/powershell/cost/start-finopscostexport) exporting the wrong period in positive UTC offsets.

For the complete list, see the [changelog](https://aka.ms/ftk/changes#v15).

## What's next

The [roadmap](https://learn.microsoft.com/cloud-computing/finops/toolkit/roadmap) now covers the rest of 2026. Here's what's in development:

- FOCUS 1.5 support across FinOps hubs, Power BI reports, agent plugins, and documentation.
- Quota, capacity, and savings plan recommendations in FinOps hubs, along with dashboards for AI billing, tokenomics, and capacity.
- Security hardening for hubs, including opt-in Key Vault role-based access control and the option to disable storage Shared Key access.
- A FinOps and capacity SRE Agent template, and AI-assisted triage to help us keep up with issues.
- Cross-cloud cost ingestion and a Terraform module for FinOps hubs.

None of this has dates, and the roadmap is driven by what you tell us you need. [Create an issue](https://aka.ms/ftk/ideas) or [start a discussion](https://aka.ms/ftk/discuss) and let us know what you'd like to see next.
